# rsleigh v0.7.0 release notes

Follow-up to the REA benchmark of v0.6.1
([morluto/rea#1389](https://github.com/morluto/rea/issues/1389)): `--all` on
large Windows binaries now finishes, and much more of the pseudocode is valid
C. Install the [v0.7.0 CLI](https://crates.io/crates/rsleigh/0.7.0) with:

```bash
cargo install rsleigh --version 0.7.0 --locked
```

Prebuilt archives for macOS (arm64/x86-64), Linux glibc (arm64/x86-64), and
Windows x86-64 are on the
[v0.7.0 release page](https://github.com/ShaneBreazeale/rsleigh/releases/tag/v0.7.0),
each with a SHA-256 checksum.

## Highlights

- **`--all` finishes.** On CrashLoggerSSE 1.25.0 (3.2 MB, with its 32 MB
  PDB) `rsleigh FILE --all --json` took longer than 40 minutes and printed
  nothing. It now takes 41 s on 10 threads (239 s on one), with identical
  output for any thread count. Three causes:
  - one function never finished (exponential condition printing);
  - imports, PDB, and DWARF were re-derived for every function;
  - everything ran on one thread with no per-function limit.

  New flags: `--jobs N` and `--fn-timeout SECS`.
- **More valid C.** In 600 sampled CrashLoggerSSE functions checked with
  `clang -fsyntax-only`, 34% compile; in REA's check, none of the five did.
  The main fixes:
  - field accesses on untyped values get a packed struct or a cast;
  - stack slots and leftover registers are declared;
  - calls through temporaries print what they call (`__fastfail(5)`);
  - C++ names print as C identifiers;
  - conditions are parenthesized by C precedence.
- **Fewer wrong results.** These were wrong before, not just invalid C:
  - registers loaded through a pointer had their load deleted (read without
    being set in 2,772 of 3,889 functions; now 2,138);
  - MSVC `/GS` functions returned the cookie check's result;
  - MSVC/clang-cl jump tables were not recovered (0 → 73 on CrashLoggerSSE).
- **Partial results are reported.** Plain decompile prints a warning, gives
  each `--json` function a `status`, and exits 2 when a body stops at a
  branch it could not follow or at the time limit.

The full list is in the [changelog](../../CHANGELOG.md).

## Migration

- **Exit status.** Plain decompile and `--all` exit 2 when any function is
  partial; they exited 0. Treat 2 as "output produced, some bodies
  incomplete", as the agent operations already do.
- **Output text.**
  - Pseudocode may begin with `#pragma pack` / `struct s_<function>_<base>`
    definitions before the signature. Use
    `rsleigh_decompile::signature_line()` instead of the first line to find
    the signature.
  - C++ names are spelled `std__exception__vftable`.
  - `int 0x29` prints as `__fastfail(code)`.
- **JSON.** `--all --json` / `FUNCTION... --json` functions gain `status`
  and `diagnostics`. The document is streamed but is still one object with
  the same keys.

Agent schemas, evidence identity, and the agent flag catalog are unchanged.

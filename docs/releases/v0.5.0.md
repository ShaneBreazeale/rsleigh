# rsleigh v0.5.0 release preparation

Status: unreleased. This minor release introduces versioned evidence schema
changes and experimental Rust analysis API changes. The v0.4.3 downloads remain
the published installation option until release artifacts are available.

## Release notes

Agents can ask where a call argument, return value, or branch condition comes
from in one bounded query. Semantic selectors resolve against the same SSA
snapshot used for traversal; snapshot-local variable selection remains available.
Slices follow supported exact memory stores and helper argument/return bindings,
retaining separate contexts for repeated calls and explicit unresolved boundaries.

Cards and slices can reuse complete decoded/SSA analysis through
`--analysis-cache DIR`. Decode and SSA work allowances, cooperative deadlines,
and separate traversal caps retain available evidence when analysis stops.
Immutable snapshots and index generations use identity checks, checksums, and
atomic publication. Interrupted work is never published as complete analysis.

Typed raw P-code operations and instruction origins make recovered values
traceable through folding, copies, and phi nodes. Decoder generation now fixes
subtable emission order, keeping raw operation indices stable across fresh builds.

Validation includes an 18-task, six-architecture corpus with answer and origin
checks across uncached, cold-cache, and warm-cache states, plus PE64 SEH-SMC
fixtures and native dependency regressions. See the
[evaluation](../agent-re-evaluation.md) for measured results and limitations.

## Migration

| Artifact | Current schema / behavior |
|---|---|
| Function card JSON | `rsleigh.card/v2`; add `--json` to the default text card |
| P-code JSON | `rsleigh.pcode/v2`; typed `operation` plus readable `op` |
| Dependency slice | `rsleigh.ssa-slice/v3`; node identity is `(context_id, var_id)` |
| Operation origins | `raw-pcode/v1`; indices refer to decoder output before optimization |
| Index manifest | Version 2; pin a verified immutable generation |

Update consumers to validate schema versions and preserve per-function snapshot
identities. Join raw origins using the function address, instruction address,
and operation index. Retain context IDs across helper links. Legacy SSA
inspection fields remain alongside typed expressions; variable IDs are scoped
to an exact snapshot. Rebuild Rust integrations against the 0.5 crate family.
See [output migration](../output-formats.md#typed-evidence-and-origin-migration).

Raw firmware and WebAssembly use separate frontends. MIPS/RISC-V argument and
frame-memory conventions remain unsupported for dependency queries. Unknown
aliases/calls, recursion, and exhausted budgets remain explicit boundaries.
Dependency recovery is not a runtime reachability or vulnerability proof.
Universal Mach-O files require selecting a supported thin slice before analysis.

## Publication sequence

Preparation includes workspace version/dependency validation and file-list
checks for all 13 publishable crates, including generated decoder sources.
The lockfile changes only workspace package versions; dependency versions are
otherwise unchanged. The real-binary report distinguishes recovered facts,
unresolved dependencies, and unsupported roots.

Local validation passed: 365 CLI/decompiler/harness tests plus the generator
regression, all 162 corpus answer/origin checks, three card-cache benchmark
repetitions, and the five real-binary queries across three cache states. The
no-default-features `pcode-ir` check also passed. Raw artifacts:
[regressions](../../test-harness/fixtures/agent-re/results/release-validation.log.gz),
[corpus](../../test-harness/fixtures/agent-re/results/release-corpus.json.gz),
[cache](../../test-harness/fixtures/agent-re/results/release-cache.json.gz), and
[real binaries](../../test-harness/fixtures/agent-re/results/release-real-binaries.json.gz).
Hosted CI must pass for the release candidate before publication.

1. Confirm hosted CI passes for the release candidate commit and review the
   [real-binary validation](../agent-re-real-binaries.md).
2. Confirm all workspace package versions and internal dependency requirements
   use 0.5.0, and review package file lists. Generated decoder sources must be
   present before packaging.
3. Publish the workspace crates in the order encoded in
   [publish-all.sh](../../scripts/publish-all.sh). This is a separate, irreversible
   publication step; local packaging checks do not publish or verify registry
   availability of the new dependency versions.
4. Tag the validated release commit `v0.5.0` and push that tag. The
   [release workflow](../../.github/workflows/release.yml) builds five platform
   archives and publishes their SHA-256 files on GitHub.
5. Check all release assets, smoke-test the installed CLI, attach these release
   notes, and update the README download links and Context7 version list.

No version tag, package publication, or release-asset upload is performed by
this preparation document.
